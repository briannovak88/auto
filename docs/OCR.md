# Пакетное локальное OCR — этап 2

Раздел «Распознавание» обрабатывает несколько PDF в порядке списка, показывает
прогресс по файлам и страницам, позволяет скопировать общий текст или сохранить
общий DOCX. В тексте и Word отмечены имена файлов и номера страниц. DOCX
редактируется, но не повторяет исходную вёрстку таблиц и колонок.

Пригодный текстовый слой извлекается через PyMuPDF. Страницы со сканами
рендерятся и распознаются EasyOCR на русском и английском. Небольшой текстовый
заголовок поверх большого изображения не заменяет распознавание скана.
Пустые страницы отмечаются отдельно. Пакет может содержать текстовые и
сканированные страницы. На этом этапе вход — PDF, выход — текст и Word;
DOCX как входной формат OCR пока не поддерживается.

## Установка на Windows: CPU

Нужен 64-битный Python 3.12. Команды выполняются из папки, где лежат
`main.py` и `requirements-ocr.txt`, в терминале PowerShell VS Code.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install "torch>=2.5,<3" "torchvision>=0.20,<1" --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -r requirements-ocr.txt
.\.venv\Scripts\python.exe -m pip check
```

Если уже используете окружение `.venv` во внешней папке после распаковки ZIP,
вместо `.\.venv\Scripts\python.exe` используйте `..\.venv\Scripts\python.exe`.
Активация окружения для этих команд не нужна. В VS Code выберите этот же
интерпретатор через Python: Select Interpreter.

OCR-зависимости опциональны: прежний генератор работает с `requirements.txt`.
PyTorch, EasyOCR, NumPy и PyMuPDF загружаются только в OCR-воркере при обработке.
Внешняя установка Tesseract, Poppler или Microsoft Word для OCR не нужна.

## Однократная подготовка моделей

Интернет нужен для установки библиотек и первоначального скачивания моделей.
Команда скачивает официальные модели EasyOCR CRAFT и Cyrillic G2 с поддержкой
ru/en (около 95 МБ). Документы эта команда не читает и не отправляет.

```powershell
.\.venv\Scripts\python.exe -m ocr_setup --model-dir ".\models\easyocr"
.\.venv\Scripts\python.exe -m ocr_setup --model-dir ".\models\easyocr" --check
.\.venv\Scripts\python.exe main.py
```

В интерфейсе укажите ту же папку моделей. По умолчанию это
`<папка данных>/models/easyocr`. При `--data-dir "D:\OctopusData"`
готовьте модели в `D:\OctopusData\models\easyocr` или выберите их папку через
«Обзор». Можно скопировать подготовленную папку моделей на офлайн-компьютер
и выполнить `ocr_setup --check` там. Модель остаётся в памяти отдельного
процесса на весь пакет и освобождается после него. Повторное скачивание во
время OCR запрещено через `download_enabled=False`.

## NVIDIA как опция

CPU — рабочий режим по умолчанию. Для NVIDIA установите актуальный драйвер
и совместимые сборки torch/torchvision с CUDA, выбрав команду для своей
Windows-конфигурации на https://pytorch.org/get-started/locally/.
Проверка в том же окружении:

```powershell
.\.venv\Scripts\python.exe -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CUDA недоступна')"
```

После успешной проверки включите NVIDIA/CUDA в разделе «Распознавание».
Если CUDA недоступна или не хватает видеопамяти, ошибка попадёт в результат
страницы; отключите GPU и повторите пакет на CPU. Автоматического перехода
на облачное OCR нет. Замер GPU в текущей среде не выполнялся.

## Работа с пакетом

1. Добавьте PDF. Повторное добавление того же файла игнорируется; следующие
   добавленные файлы помещаются в конец. Удаляйте выбранные строки до запуска.
2. Выберите CPU/GPU, папку моделей и разрешение (по умолчанию 200 DPI).
   Для очень больших страниц размер растрового изображения ограничен 3500 px.
3. Нажмите «Распознать пакет». Можно перейти в «Документы» и вернуться:
   задача и состояние интерфейса сохраняются.
4. «Отменить» останавливает пакет после текущей операции/страницы и сохраняет
   неполный результат. Во время первой загрузки модели или сложной страницы
   отмена может занять время; окно остаётся отзывчивым.
5. После завершения доступны копирование полного текста, сохранение DOCX
   и папка результата. Предпросмотр ограничен 2 млн символов, копирование и
   DOCX содержат полный текст. Ошибки видны в тексте и подсказке строки файла.

Повреждённый PDF, PDF с паролем или ошибка отдельной страницы не прерывают
остальные файлы. В Word и тексте ставится отметка «НЕПОЛНЫЙ РЕЗУЛЬТАТ».
Отмена и ошибки дают `result-partial.docx`, успешный пакет — `result.docx`.
Повторный запуск создаёт новую папку и не заменяет прежний результат.

При закрытии окна во время OCR можно отменить задачу, дождаться сохранения
неполного результата и закрыть окно. Если параллельно работает генератор,
окно также дождётся его завершения.

## Локальные файлы и устойчивость

Каждый запуск сохраняется в `<папка данных>/ocr-results/batch-*/`:

- `request.json`, локальный файл отмены;
- `result/pages/*.txt` — завершённые страницы;
- `result/result.json` — состояние и пути к результатам;
- `result/result*.txt`, `result/result*.docx` — общий результат;
- `diagnostics.log` — локальные сообщения библиотек, если они были.

Сканы, текст и диагностические файлы не отправляются в сеть и не входят в Git.
DOCX записывается во временный файл и атомарно переименовывается. Если процесс
аварийно завершён или закрыт через диспетчер задач, под окончательным именем
не останется недописанного Word-файла. Уже записанные страницы доступны в
`pages`; незавершённый экспорт интерфейс отмечает как прерванный.

Обработка доступна из Python без QApplication:

```python
from pathlib import Path
from ocr_engine import OcrSettings, process_batch

result = process_batch(
    [Path("first.pdf"), Path("second.pdf")],
    Path("new-result-folder"),  # папка ещё не должна существовать
    OcrSettings(Path("models/easyocr"), gpu=False),
    on_event=print,
)
```

## Сборка exe

Собирать следует на Windows из окружения с обеими группами зависимостей.
Установите PyInstaller и добавьте к команде из README:

```powershell
python -m PyInstaller --noconsole --name "Octopus" --hidden-import pythoncom --hidden-import win32com.client --hidden-import win32timezone --collect-all easyocr main.py
```

Модели держите во внешней папке данных. Они не копируются в `_MEIPASS`.
В исходниках QProcess запускает `python main.py --ocr-worker request.json`,
в сборке — тот же exe с `--ocr-worker`. Этот режим выбирается до импорта Qt.
Для оконной Windows-сборки учтён вывод событий через pipe QProcess при
`sys.stdout=None`. Реальная Windows-сборка требует ручной проверки.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
.\.venv\Scripts\python.exe -m compileall -q main.py ocr_engine.py ocr_worker.py ocr_widget.py ocr_setup.py tests
```

На Windows проверьте цифровой PDF, скан ru/en, смешанный PDF, повреждённый
файл, пробелы и кириллицу в путях, отмену, повторный запуск, копирование и
общий DOCX, переключение в «Документы» во время OCR и закрытие окна.
Для своего реального пакета 50–100 страниц отдельно замерьте время и
отзывчивость. Для NVIDIA укажите модель GPU, версию CUDA/PyTorch и DPI.

Для воспроизводимого синтетического CPU-теста (папка должна быть новой):

```powershell
.\.venv\Scripts\python.exe -m tests.benchmark_ocr --models ".\models\easyocr" --output-dir "D:\Temp\Octopus-OCR-benchmark" --pages 50
```

Он создаёт повторяющиеся сканы с двумя строками ru/en, запускает настоящий
GUI/QProcess и пишет `benchmark.json` с временем, числом ошибок, проверкой
языков и интервалами контрольного таймера GUI. Синтетический замер текущей
Linux-среды описан в [отчёте OCR](OCR_REPORT.md).
