# Этап 2: пакетное локальное OCR

Реализован рабочий раздел «Распознавание» для пакета PDF. Остальные новые
разделы остаются макетами. Этап 1 и его генератор сохранены.

## Файлы и назначение

| Файл | Изменение |
| --- | --- |
| `ocr_engine.py` | Независимый от Qt пакет: извлечение текстового слоя, рендер сканов, один EasyOCR Reader на пакет, ошибки отдельных файлов/страниц, отмена, контрольные сохранения, общий текст и атомарный DOCX. |
| `ocr_worker.py` | Отдельный процесс с маленькими JSONL-событиями; текст передаётся через файлы. Учтён pipe Windows-сборки без консоли. |
| `ocr_widget.py` | Выбор нескольких PDF, порядок списка, прогресс, отмена, предпросмотр, копирование, сохранение Word, QProcess и восстановление управления после ошибок. |
| `ocr_setup.py` | Явное первоначальное скачивание моделей и офлайн-проверка ru/en. |
| `main.py` | Ранний режим `--ocr-worker` до импорта Qt; подключение рабочего OCR и ожидание фоновых задач при закрытии окна. |
| `ui_shell.py` | Описание рабочего входа PDF и выхода Word. |
| `requirements-ocr.txt`, `.gitignore` | Отдельные зависимости OCR, исключения моделей и локальных результатов. |
| `tests/ocr_fixtures.py`, `tests/test_ocr.py`, `tests/test_ocr_gui.py` | Синтетические PDF и проверки ядра, протокола, отмены, экспорта, QProcess и GUI. |
| `tests/test_gui.py` | Проверка рабочего OCR вместо прежнего макета. |
| `tests/benchmark_ocr.py` | Воспроизводимый синтетический CPU-замер 1–100 страниц через GUI. |
| `README.md`, `docs/OCR.md`, `REPORT.md` | Установка, модели, CPU/CUDA, запуск, Python API, сборка и ограничения. |
| `docs/previews/octopus-recognition.png` | Новый снимок работающего интерфейса на синтетическом пакете. |

## Проверки

Выполнены в Linux / Python 3.12.14, EasyOCR 1.7.2, PyMuPDF 1.28.2,
PyTorch 2.15.0+cpu. Использован интерпретатор уже подготовленного окружения:

```bash
../automat-docs/.venv/bin/python -m pip install 'torch>=2.5,<3' 'torchvision>=0.20,<1' --index-url https://download.pytorch.org/whl/cpu
../automat-docs/.venv/bin/python -m pip install -r requirements-ocr.txt
../automat-docs/.venv/bin/python -m ocr_setup --model-dir /workspace/work/ocr-models
../automat-docs/.venv/bin/python -m ocr_setup --model-dir /workspace/work/ocr-models --check
QT_QPA_PLATFORM=offscreen ../automat-docs/.venv/bin/python -m unittest discover -v
../automat-docs/.venv/bin/python -m compileall -q main.py ocr_engine.py ocr_worker.py ocr_widget.py ocr_setup.py ui_shell.py tests
../automat-docs/.venv/bin/python -m pip check
git diff --check
```

**37 тестов прошли.** Проверены цифровой PDF без моделей, пустая страница,
скан и смешанные страницы, повреждённый PDF, файл с паролем, кириллица и
пробелы в путях, порядок файлов и границы страниц, один Reader без скачивания,
ошибка моделей/CUDA, отмена до начала/между страницами/при экспорте,
повторный запуск и отсутствие окончательного DOCX при ошибке записи.

Настоящий `main.py --ocr-worker` запущен из другого cwd с недействительной
платформой Qt — обработка завершается без QApplication. В GUI проверены
реальный QProcess, прогресс, копирование текста, экспорт DOCX, доступность
«Документов», отмена, закрытие с ожиданием и ошибка запуска процесса.
Предыдущие тесты генератора шести DOCX также прошли.

Модели CRAFT и Cyrillic G2 скачаны официальной командой EasyOCR, затем
успешно проверены с отключёнными скачиваниями. Во время OCR сканы и текст
остаются локальными. Модели и результаты тестов в Git не добавлены.

## Замер CPU

Замер выполнен через настоящий GUI и QProcess на 50 синтетических
сканированных страницах без текстового слоя. На каждой странице — две
строки, русская и английская, шрифт DejaVu Sans. Это повторяющиеся страницы
700×225 pt, 200 DPI, CPU, до четырёх потоков PyTorch. Замер включает
первоначальную загрузку Reader в OCR-процессе. Это технический тест нагрузки,
а не замер на пользовательских документах A4.

Результат: **50/50 страниц, 0 ошибок**, 408,348 с в движке, 409,507 с
с учётом запуска процесса и обновления GUI (примерно 6 мин 49 с).
Контрольный таймер GUI с периодом 50 мс сработал 8163 раза; максимальный
промежуток между срабатываниями — 0,205 с. В общем тексте найдены обе
контрольные строки: «Осьминог: тест распознавания» и
«Octopus local OCR test 2026». Итоговый DOCX создан.

Замер выполнен командой `QT_QPA_PLATFORM=offscreen ../automat-docs/.venv/bin/python
/workspace/work/ocr_smoke_run.py` (временный сценарий с указанными параметрами).
В репозитории добавлен эквивалентный `tests.benchmark_ocr` для повторения
замера на Windows; команда приведена в инструкции OCR. Время не переносится
на другой CPU, DPI и документы автоматически.

## Ограничения и Windows

- Реальный пользовательский пакет 50–100 страниц не предоставлен. Его
  скорость и качество нужно измерить отдельно на целевом компьютере.
- NVIDIA/CUDA в среде не доступны; GPU-замер и поведение при нехватке VRAM
  требуют проверки на Windows с указанием GPU, PyTorch/CUDA и DPI.
- Экспорт OCR создаётся через python-docx и не требует Word. Оригинальная
  вёрстка таблиц, колонок и иллюстраций не восстанавливается.
- PDF — вход этого этапа, общий DOCX и текст — выход. Входной Word не добавлен.
- Отмена кооперативная: она ждёт завершения текущей загрузки модели/страницы.
  Если процесс завершён извне, сохранённые страницы доступны в `pages`, а
  незавершённый DOCX не появляется под окончательным именем.
- Windows exe, стандартные потоки оконной сборки и масштабирование интерфейса
  нужно проверить на Windows; варианты запуска воркера учтены в коде и тестах.
- Microsoft Word/PDF прежнего генератора в этой среде по-прежнему не проверен.

Конкретные команды установки, подготовки моделей и сборки, а также сценарий
ручной проверки Windows находятся в [инструкции OCR](OCR.md).
