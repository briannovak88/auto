# Осьминог (Octopus)

Настольное приложение PyQt6 с общим рабочим пространством и боковой навигацией.
Работают «Документы» с двумя вкладками генератора и пакетное «Распознавание» PDF.
Введённые данные остаются в памяти при переключении экранов.

По прототипу добавлено синее оформление: боковая панель, верхний баннер,
светлые карточки и единый стиль кнопок. При выборе раздела меняются заголовок
окна, значок, аватар боковой панели, название и описание в баннере.
Кнопки открепления PNG и PFX выровнены по правому краю полей карточки автора;
длинные имена файлов сокращаются на экране.

В меню также доступны макеты «Текст», «Конспект», «Источники», «Код и документы»,
«Сортировка файлов». Функции этапов 3–7 пока запланированы.

Название «Осьминог» пока временное. Для совместимости прежние пути данных
`Automat docs` и переменные `AUTOMAT_DOCS_*` сохранены, данные не переносятся.
Значки рисуются средствами PyQt6/QtSvg; дополнительные библиотеки не нужны.

Примеры интерфейса с синтетическими данными:
[документы](docs/previews/octopus-documents.png),
[распознавание](docs/previews/octopus-recognition.png).

## Запуск на Windows

До слияния изменений этапа 1 используйте его отдельную ветку:

```powershell
git clone https://github.com/briannovak88/auto.git
cd auto
git switch codex/stage-1-documents-shell
```

Нужен Python 3.10 или новее. Из папки проекта:

```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python main.py
```

Обычная точка входа `python main.py` сохранена. Для существующего проекта
оставьте рядом с исходниками папки `database`, `signatures`, `templates`.
Рабочие шаблоны не входили в предоставленные материалы: используйте свои
локальные шаблоны или отдельные синтетические данные по инструкции ниже.

Запуск из другой рабочей папки с указанием проекта:

```powershell
D:\AutomatDocs\.venv\Scripts\python D:\AutomatDocs\main.py --project-dir "D:\AutomatDocs"
```

Отдельное хранение данных, базы и редактируемых шаблонов:

```powershell
python main.py --data-dir "D:\Мои документы\AutomatDocs" --templates-dir "D:\Мои шаблоны"
python main.py --db-path "D:\Старый проект\database\authors.db" --templates-dir "D:\Старый проект\templates"
```

`--data-dir` — корень, содержащий `database/authors.db`, `signatures/png`,
`signatures/pfx`; результаты по умолчанию находятся в его `output`.
`--db-path` выбирает существующую базу без её переноса. Если папка базы называется
`database`, корнем данных будет её родитель; иначе — папка самой базы.
При другом расположении подписей дополнительно укажите `--data-dir`.

Те же параметры можно задать переменными окружения:

| Параметр | Переменная |
| --- | --- |
| `--project-dir` | `AUTOMAT_DOCS_PROJECT_DIR` |
| `--data-dir` | `AUTOMAT_DOCS_DATA_DIR` |
| `--db-path` | `AUTOMAT_DOCS_DB_PATH` |
| `--templates-dir` | `AUTOMAT_DOCS_TEMPLATES_DIR` |

Явный параметр имеет приоритет над одноимённой переменной. Относительные пути
параметров запуска считаются от текущей рабочей папки. В полях интерфейса
относительная папка шаблонов считается от папки проекта, выходная — от папки данных.

В исходниках корень данных по умолчанию — папка исходников, в сборке —
`%LOCALAPPDATA%\Automat docs`. Существующая `database/authors.db` рядом с exe
поддерживает прежнее переносимое расположение. Без явного пути приложение
также проверяет базу в текущей рабочей папке и стандартной папке данных.
Если обнаружено несколько разных баз, откроется диалог выбора файла; можно
выйти без открытия базы. Автоматического переноса, копирования или замены базы нет.
При первом открытии сохраняется прежнее добавление недостающих колонок схемы.
Для проверки старой базы используйте её копию вместе с папкой `signatures`.

Относительные ссылки на подписи считаются от корня данных; старые абсолютные
ссылки тоже читаются. Новые подписи сохраняются с относительными ссылками.
Недоступные ссылки не удаляются при редактировании карточки.

## Распознавание

Установка и использование OCR описаны отдельно: [Распознавание PDF](docs/OCR.md).
Сначала установите CPU- или CUDA-сборку PyTorch, затем `requirements-ocr.txt`
и подготовьте модели ru/en командой `ocr_setup`. Генератор не требует этих зависимостей.

## Генерация

Добавьте авторов, загрузите модули из папки листингов или Excel либо введите
их вручную. Выберите авторов модуля, основного автора, дату и выходную папку.
После генерации таблица показывает пересчитанное число страниц листинга,
открывается папка результатов. Во время обработки редактирование задания
временно отключено. При закрытии окна можно продолжить работу или дождаться
окончания генерации и автоматически закрыть окно.

Ожидаемые имена шаблонов в `templates`:

```text
1. Заявление лицо (шаблон).docx
2. Дополнение к заявлению (шаблон).docx
3. Согласия (паспорта) (шаблон).docx
4. Указания сведений (шаблон).docx
5. Ходатайство об освобождении платы (шаблон).docx
6. Листинг (шаблон).docx
```

Поддерживаются прежние альтернативные имена без ` (шаблон)`. Исправление
тегов docxtpl и строки даты выполняется на временной копии с тем же именем;
исходные шаблоны не записываются. В комплект входят шесть прежних DOCX.

PNG вставляется как изображение подписи. PFX сохраняется в карточке автора;
электронное подписание документов на этом этапе не реализовано.

Точный подсчёт страниц и экспорт PDF используют установленный настольный
Microsoft Word через COM. `pywin32` явно включён в зависимости только Windows.
Без Word работает резервная оценка страниц; для DOCX Word не обязателен.
При ошибке PDF показывается сообщение, созданные DOCX сохраняются.

Обработка доступна без QApplication: `AuthorDB` из `db.py`, импорт и
`generate_module_documents()` из `generator.py`. При относительных ссылках на
подписи в отдельном скрипте передайте `data_dir=Path(...)` в генератор.

## Синтетическая проверка

Создайте новую папку, отличную от рабочих данных:

```powershell
python -m tests.make_demo --dest "D:\Temp\AutomatDocs-demo"
python main.py --data-dir "D:\Temp\AutomatDocs-demo"
```

В ней будут старая схема SQLite с вымышленным автором, искусственная PNG,
файл с тестовыми байтами вместо PFX, шесть минимальных шаблонов, листинг
и Excel. Это технические фикстуры, не шаблоны для подачи документов.
Повторное создание в существующей папке запрещено, чтобы не перезаписать данные.

Проверки из корня проекта:

```powershell
python -m unittest discover -v
python -m compileall -q main.py ui_shell.py db.py generator.py app_paths.py tests
```

Тесты GUI используют `QT_QPA_PLATFORM=offscreen`; все данные создаются во
временных папках. В репозитории нет рабочей базы, сканов и подписей.

## Сборка и ручная проверка Windows

Файл `Automat docs.spec` не был предоставлен. Для проверки новой сборки
можно использовать следующую команду из Windows-окружения с зависимостями:

```powershell
python -m pip install pyinstaller
python -m PyInstaller --noconsole --name "Automat docs" --hidden-import pythoncom --hidden-import win32com.client --hidden-import win32timezone main.py
& ".\dist\Automat docs\Automat docs.exe" --data-dir "D:\Temp\AutomatDocs-demo"
```

Не включайте рабочую базу и подписи в сборку. Пользовательские шаблоны
держите во внешней папке и указывайте `--templates-dir` либо `data-dir/templates`.
Если нужны обезличенные встроенные шаблоны, добавьте к команде сборки
`--add-data "templates;templates"`: они будут читаться из ресурсов PyInstaller,
а редактируемая внешняя папка `templates` имеет приоритет. Ресурсы `_MEIPASS`
не используются для базы, подписей и результатов.

На Windows проверьте импорт папки и Excel, ручной модуль, смену основного
автора и даты, шесть DOCX, неизменность исходных шаблонов, обновление страниц
в таблице и закрытие во время генерации. С установленным Word проверьте
PDF и PNG в нём; без Word — оценку страниц и сообщение об ошибке PDF.
Затем повторите запуск exe из другой папки с явным `--data-dir`.
Реальный Word и Windows exe в Linux-среде не проверялись. NVIDIA и API-ключи
для этапа 1 не требуются.
