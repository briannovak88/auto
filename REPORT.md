# Отчёт: Осьминог (Octopus), этап 1 и оформление

Выполнен только этап 1 по трём приложенным исходникам. Раздел «Документы»
встроен в общее окно; обе прежние вкладки сохранены. По дополнительному запросу
пользователя применён дизайн по прототипу и временное название «Осьминог».
Этот отчёт относится к этапу 1 и оформлению. Этап 2 (OCR) реализован следующим
коммитом; актуальные проверки и ограничения — в [отчёте OCR](docs/OCR_REPORT.md).
Для этапов 3–7 сохранены макеты экранов.

## Исходные материалы

Основа — приложенные `main.py`, `db.py`, `generator.py`. После подготовки
этапа пользователь подключил https://github.com/briannovak88/auto. Проверка
GitHub показала пустой репозиторий без файлов и коммитов. Три исходных файла
загружены в `main` как базовая версия; для этапа 1 создана отдельная ветка
`codex/stage-1-documents-shell`.

После клонирования `git status --short` показал чистое рабочее дерево;
проверен фактический список файлов. AGENTS.md, README, шаблонов, зависимостей
и `Automat docs.spec` в исходной базе нет. Рабочая SQLite, реальные подписи
и пользовательские документы не предоставлялись и в Git не добавлялись.

## Выполненные проверки

Среда: Linux, Python 3.12.14, PyQt6 6.12.0, Qt 6.12.0,
docxtpl 0.20.2, python-docx 1.2.0. Зависимости установлены в отдельный `.venv`.

Команды из корня подготовленного проекта:

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
QT_QPA_PLATFORM=offscreen .venv/bin/python -m unittest discover -v
.venv/bin/python -m compileall -q main.py ui_shell.py db.py generator.py app_paths.py tests
.venv/bin/python -m pip check
.venv/bin/python main.py --help
.venv/bin/python -m tests.make_demo --dest '/workspace/work/AutomatDocs demo'
git diff --check
```

Результат после обновления дизайна: **22 теста прошли**, компиляция без ошибок, `pip check` —
`No broken requirements found`, проверка пробелов диффа без ошибок.
В offscreen-режиме Qt были сообщения о недоступном кеше шрифтов и
`propagateSizeHints`; запуск окна и тесты завершились успешно.

После переноса в клон GitHub-репозитория тесты и компиляция повторены
интерпретатором уже подготовленного окружения:

```bash
QT_QPA_PLATFORM=offscreen ../automat-docs/.venv/bin/python -m unittest discover -v
../automat-docs/.venv/bin/python -m compileall -q main.py ui_shell.py db.py generator.py app_paths.py tests
git diff --check
```

Дополнительно окно с синтетической базой открыто в offscreen-режиме;
просмотрены снимки документов, генерации и распознавания. Проверено окно
1672×945 и уменьшение до 1366×768 с доступом к форме через прокрутку.
Smoke-тест выполняет настоящий блок `__main__`
из другой папки с `--data-dir` и автоматически закрывает GUI таймером.
Это проверка запуска PyQt6 в Linux, не проверка интерактивной работы Windows.

Проверены:

- Миграция тестовой копии старой SQLite, включая схему без полей подписей;
  исходная тестовая база до копирования осталась побайтно прежней.
- Относительные Windows-ссылки с обратной косой чертой, абсолютные ссылки,
  PNG в DOCX и сохранение PFX в карточке без электронного подписания.
- Импорт папки DOCX/PDF/исходников и Excel с исключением дублей.
- Из одного модуля созданы ровно шесть ожидаемых DOCX; подставлены дата,
  автор и страницы. Листинг с кириллицей и символами `<>&` читается корректно.
- Все шесть шаблонов побайтно совпали до и после генерации; временные копии
  удаляются также после исключения. Проверен исходный шаблон «только чтение».
- Сохранение полей при переходе на «Распознавание» и обратно. Для всех семи
  разделов проверены заголовок окна, баннер, описание и аватар; значок меняется.
  Для макетов показано сообщение о запланированных функциях.
- Правый край обоих крестиков совпадает с полем «Творческий вклад» при двух
  размерах окна. Длинное имя не перекрывает кнопки; открепление PNG/PFX работает.
- Основной автор идёт первым, ручное число страниц сохраняется, пересчитанные
  страницы появляются в таблице, в том числе при последующей ошибке PDF.
- Закрытие с отказом и с ожиданием, завершение потока во время диалога закрытия,
  повторная генерация после ошибки, независимая копия входных данных потока.
- Выбор при неоднозначной базе, запуск с явным проектом/данными из другого cwd,
  разделение ресурсов PyInstaller и пользовательских данных через имитацию frozen.

## Что проверить на Windows

1. Создайте окружение и установите `requirements.txt` по README. Создайте
   новую тестовую папку командой `python -m tests.make_demo --dest "D:\Temp\AutomatDocs-demo"`.
   Запустите `python main.py --data-dir "D:\Temp\AutomatDocs-demo"`.
2. В «Документы» проверьте карточку старого автора, PNG/PFX, редактирование
   и сохранение. Импортируйте папку `листинги` и файл `модули.xlsx`, добавьте
   модуль вручную, выберите авторов, основного автора и дату.
3. Отключите PDF и создайте комплект: в папке модуля должно быть шесть DOCX
   с прежними именами, датой и PNG; число страниц должно обновиться в таблице.
   Сравните шаблоны до и после, например через `Get-FileHash` в PowerShell.
4. С установленным Microsoft Word включите PDF. Проверьте шесть PDF,
   отображение PNG и совпадение страниц листинга с Word. На машине без Word
   проверьте резервную оценку и понятное сообщение PDF с сохранением DOCX.
5. Во время пакета закройте окно: «Нет» оставляет работу, «Да» закрывает
   после завершения. Повторите генерацию после ошибки пути или PDF.
6. Запустите из другой папки с `--project-dir` и отдельно с `--data-dir`.
   Для проверки нескольких баз разместите разные тестовые копии в папке
   проекта и текущем cwd и запустите без явных путей: должен появиться выбор.
7. Соберите exe на Windows командой из README. Запустите exe из другой папки
   с тестовым `--data-dir`, повторите генерацию DOCX/PDF. Рабочую базу,
   подписи и секреты не включайте в ресурсы сборки.
8. Проверьте внешний вид при масштабировании Windows 100%, 125% и 150%:
   смену шапки и значка, возврат к несохранённой карточке автора, выравнивание
   крестиков и прокрутку формы при небольшом окне. Переключитесь на
   «Распознавание» во время генерации, затем закройте окно с ожиданием.

**Microsoft Word:** настоящий COM, точная пагинация и PDF не проверялись;
проверены резервная оценка, сообщения ошибок и вызовы с имитацией COM.
**Windows exe:** сборка и запуск не выполнялись; предоставленного `.spec` нет,
команда сборки в README требует проверки на Windows.
**NVIDIA и API-ключи:** этап 1 их не использует и не требует.

## Версия для проверки

В `main` находится исходная версия трёх приложенных файлов. Изменения этапа 1
размещаются в `codex/stage-1-documents-shell` и доступны для проверки через
pull request. В ветке только исходники, зависимости, документация и тесты;
`.venv`, SQLite, подписи и результаты генерации не включены.

Для запуска ветки используйте команды клонирования и выбора ветки из README.
Сравнение с исходными файлами доступно в GitHub во вкладке Files changed.
Слияние с `main` и дальнейшие этапы не выполнялись.
